# OpenAPI 代码生成与本地跨域代理

这份文档解决两个高频问题：

1. `pnpm openApi` 到底怎么用
2. 本地开发时，多后端服务怎么优雅处理跨域

---

## 1. 先记住这两个命令

### 生成 OpenAPI 接口代码

```bash
pnpm openApi
```

### 自动生成模块配置模板

```bash
pnpm openApi:modules
```

---

## 2. 这套方案的目标

项目希望把下面几件事自动化：

- 根据 OpenAPI 文档生成前端请求代码
- 按模块拆分 API 目录
- 在本地开发时自动适配代理前缀
- 避免手写大量重复的 interface / request 代码

---

## 3. 相关目录先认清

```text
openApi/
├── index.ts                # openApi 主入口
├── genModules.ts           # 模块配置自动生成入口
├── modules/                # 模块配置
└── generate/               # 生成器核心逻辑与模板
```

生成结果默认会落到：

```text
src/api/
```

---

## 4. `pnpm openApi` 做了什么

执行后会：

1. 读取 `openApi/index.ts` 中配置的数据源
2. 拉取或读取 OpenAPI JSON
3. 根据模板生成 TypeScript 类型和请求方法
4. 输出到 `src/api/` 下对应目录

适合你在这些场景用：

- 后端接口文档已经稳定
- 需要批量生成接口定义
- 项目模块多，手写接口成本高

---

## 5. `pnpm openApi:modules` 做了什么

执行后会去请求后端模块清单接口：

```text
GET ${OPENAPI_BASE_URL}/api/getModules
```

然后自动在 `openApi/modules/` 下生成模块模板，方便你按模块启用。

典型用途：

- 后端接口很多，需要先选模块再生成
- 你想把 API 生成范围控制得更细

---

## 6. 本地开发为什么会跨域

因为浏览器不允许页面直接跨域访问不同的域名或端口。

比如：

- 前端：`http://localhost:5173`
- 用户服务：`http://192.168.1.100:8080`
- 订单服务：`http://192.168.1.101:9090`

这时直接请求就会碰到 CORS 问题。

---

## 7. 当前项目怎么解决跨域

核心思路：

> **Vite Proxy + OpenAPI 生成时自动注入代理前缀**

### 第一步：在 `build/config/proxy.ts` 配代理

给不同后端服务分配不同前缀，例如：

```ts
'/apiUser': {
  target: 'http://192.168.1.100:8080',
  changeOrigin: true,
  rewrite: path => path.replace(/^\/apiUser/, ''),
}
```

### 第二步：OpenAPI 文档里带上 `servers`

例如：

```json
{
  "servers": [{ "url": "http://192.168.1.100:8080" }]
}
```

### 第三步：运行 `pnpm openApi`

生成器会自动识别：

- 这个服务对应哪个代理目标
- 应该给请求补哪个代理前缀

最终生成的请求 URL 会自动变成：

```ts
url: '/apiUser/users/1'
```

这样浏览器访问的是本地前端服务，真正的跨域转发由 Vite 代理完成。

---

## 8. 常见排查

### 1）生成的请求没有代理前缀

优先检查：

- OpenAPI JSON 是否包含 `servers`
- `servers[0].url` 是否和 `build/config/proxy.ts` 的 `target` 对得上

### 2）请求返回 404

优先检查：

- `rewrite` 是否把前缀正确去掉了
- 真实后端路径是否存在

### 3）请求返回 HTML 而不是 JSON

这通常说明请求没有命中代理，而是落回前端页面。

优先检查：

- 请求 URL 是否真的带了代理前缀
- 代理规则是否配置正确

### 4）生成结果为空或结构异常

优先检查：

- OpenAPI JSON 是否合规
- `openApi/index.ts` 中的数据源配置是否正确
- 模板是否被改坏

---

## 9. 推荐工作流

1. 先配好 `build/config/proxy.ts`
2. 确认后端 OpenAPI 文档里带 `servers`
3. 运行 `pnpm openApi:modules`
4. 精简模块配置
5. 运行 `pnpm openApi`
6. 在页面里接入生成好的接口
