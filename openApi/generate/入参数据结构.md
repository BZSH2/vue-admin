# ApiGenerator 入参数据结构与本地开发跨域指南

本文档详细说明 `ApiGenerator` 的数据结构定义、支持的组织方式，以及在本地开发中如何处理**多服务跨域**问题。

## 1. 类型定义

### 1.1 `APIDataType`

`APIDataType` 是一个递归类型，可以表示单个 OpenAPI 对象、OpenAPI 对象数组，或者是嵌套的字典结构。

```typescript
type APIDataType =
  | OpenAPIObject // 单个 OpenAPI 对象
  | OpenAPIObject[] // OpenAPI 对象数组
  | { [key: string]: APIDataType } // 嵌套字典（按模块分组）
  | APIDataType[] // 嵌套数组
```

### 1.2 `OpenAPIObject`

标准的 OpenAPI 3.0/3.1 规范对象，包含 `openapi`、`info`、`paths`、`components`、`servers` 等核心字段。

## 2. 数据结构示例

支持扁平数组、嵌套字典或混合结构，详见下文。

### 2.1 扁平数组结构 (最简单)

```javascript
const apiData = [
  { openapi: '3.0.1', info: { title: 'UserAPI' }, paths: { ... } },
  { openapi: '3.0.1', info: { title: 'OrderAPI' }, paths: { ... } }
];
```

### 2.2 嵌套字典结构 (按模块分组)

```javascript
const apiData = {
  "SaaS模块": [
    { openapi: '3.0.1', info: { title: 'TenantService' }, paths: { ... } }
  ],
  "电商模块": {
    "交易中心": [
      { openapi: '3.0.1', info: { title: 'PaymentService' }, paths: { ... } }
    ]
  }
};
```

## 3. 本地开发多服务跨域方案 (重点)

在微服务架构下，前端往往需要对接多个不同的后端服务（如 `UserCenter`, `OrderCenter`, `PaymentService`），每个服务可能部署在不同的域名或端口下。本地开发时，我们需要解决以下问题：

1.  **跨域请求**：浏览器限制跨域访问。
2.  **路径转发**：将前端请求转发到正确的后端服务。
3.  **代码生成**：生成的 API 请求代码需要自动适配代理路径。

### 3.1 解决方案概览

本脚手架通过 **Vite Proxy** + **自动前缀注入** 的方式完美解决了上述问题。

1.  **配置代理**：在 `build/config/proxy.ts` 中配置多个代理规则。
2.  **自动匹配**：`ApiGenerator` 在生成代码时，会自动检测 OpenAPI 中的 `servers.url`。
3.  **注入前缀**：如果 `servers.url` 命中了某个代理规则，生成器会自动将对应的**代理前缀**（如 `/apiUser`）拼接到请求 URL 上。

### 3.2 配置步骤

#### 第一步：配置 Vite 代理 (`build/config/proxy.ts`)

为每个后端服务配置一个唯一的代理前缀。

```typescript
// build/config/proxy.ts
export function createViteProxy() {
  return {
    // 1. 用户中心服务
    '/apiUser': {
      target: 'http://192.168.1.100:8080', // 真实后端地址
      changeOrigin: true,
      rewrite: (path) => path.replace(/^\/apiUser/, ''), // 移除前缀
    },
    // 2. 订单中心服务
    '/apiOrder': {
      target: 'http://192.168.1.101:9090',
      changeOrigin: true,
      rewrite: (path) => path.replace(/^\/apiOrder/, ''),
    },
  }
}
```

#### 第二步：确保 OpenAPI 数据包含 `servers` 信息

后端返回的 OpenAPI JSON 中必须包含 `servers` 字段，且 `url` 必须与 `target` 匹配（或为 `target` 的子路径）。

```json
{
  "openapi": "3.0.1",
  "info": { "title": "UserService" },
  "servers": [
    { "url": "http://192.168.1.100:8080" } // 必须与 proxy 中的 target 匹配
  ],
  "paths": { ... }
}
```

#### 第三步：自动生成代码

运行 `pnpm openApi`。生成器会自动检测：

- OpenAPI `servers[0].url` 是 `http://192.168.1.100:8080`
- 发现它匹配了代理配置中的 `/apiUser`
- 生成的请求代码会自动带上 `/apiUser` 前缀

**生成的代码示例 (`src/api/User/UserService.ts`)**:

```typescript
export function getUser(id: string) {
  return request({
    // 自动拼接了 /apiUser 前缀，确保请求能命中 Vite 代理
    url: `/apiUser/users/${id}`,
    method: 'GET',
  })
}
```

### 3.3 常见问题排查

1.  **生成的 URL 没有前缀？**
    - 检查 OpenAPI JSON 是否包含 `servers` 字段。
    - 检查 `servers[0].url` 是否与 `proxy.ts` 中的 `target` 完全一致（包括 `http/https` 和末尾斜杠的处理）。

2.  **请求 404 Not Found？**
    - 检查 `proxy.ts` 中的 `rewrite` 规则。通常需要移除前缀：`path.replace(/^\/apiPrefix/, '')`。
    - 检查 `request` 封装（`src/utils/request`）中的 `baseURL`。建议设置为 `'/'`，避免重复拼接（如 `/api/apiUser/...`）。

3.  **浏览器 Network 显示请求成功，但返回 HTML？**
    - 这通常意味着请求没有被代理拦截，而是落到了 Vite 开发服务器上（Fallback 到 index.html）。
    - 请检查请求 URL 是否正确以代理前缀开头。

## 4. 处理逻辑 (`generateApi` 方法)

生成器采用递归方式处理 `apiData`，逻辑如下：

1.  **数组处理**: 遍历数组，如果是 OpenAPI 对象则生成代码，否则递归。
2.  **对象处理**:
    - **OpenAPI 对象**: 生成代码。
    - **普通对象**: 视为目录容器，Key 作为子目录名，递归处理 Value。

## 5. 注意事项

- **递归深度**: 建议保持结构扁平。
- **命名冲突**: 文件夹名称取自 `info.title`，确保唯一。
- **数据校验**: 确保传入的 OpenAPI 对象符合标准规范。

## 6. 模块配置自动生成（openApi:modules）

在开始接入 OpenAPI 之前，可通过命令自动生成模块配置文件，便于选择要导出的模块与服务。

- 命令
  - `pnpm openApi:modules`
  - 环境变量：`OPENAPI_BASE_URL`（默认 `http://localhost:3000`）
- 数据来源
  - GET `${OPENAPI_BASE_URL}/api/getModules`
  - 返回结构：
    ```json
    {
      "code": 200,
      "message": "success",
      "data": [
        {
          "prefix": "Users",
          "label": "Users",
          "service": [
            { "value": "UsersController_create", "label": "创建用户 (管理员)" },
            { "value": "UsersController_findOne", "label": "根据ID查询用户" }
          ]
        }
      ]
    }
    ```
- 生成产物
  - 输出目录：`openApi/modules/generated`
  - 文件名：基于 `prefix` 规范化并转小驼峰（如 `OpenAPI` → `openAPI.ts`）
  - 模板：`openApi/generate/generateTemplate/templates/openApiModule.njk`
  - 输出示例：
    ```ts
    export default {
      /** Users */
      prefix: 'Users',
      service: [
        // '*',
        // 'UsersController_create', /** 创建用户 (管理员) */
        // 'UsersController_findOne', /** 根据ID查询用户 */
      ],
    }
    ```
- 自动聚合
  - 入口文件：`openApi/modules/index.ts`
  - 行为：在 Vite 环境下使用 `import.meta.glob('./generated/*.ts', { eager: true })` 自动收集；在脚本环境下回退到读取 `generated` 目录中所有 `.ts` 文件

> 提示：服务列表以注释形式输出，便于逐项启用；也可通过 `'*'` 进行全选统配。
